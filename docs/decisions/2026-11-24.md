# 2026-11-24

0.2.0 lite install, first part: the backend's own credentials for Prometheus.

- **Prometheus auth setting** (Contract 2, `settings` row `prometheus_auth`): optional basic or bearer auth from the backend to Prometheus, the secret encrypted with the master key under its own row context, backed up and restored, and counted as a stored secret by the key check, restore and `rotate-master-key`. New; until now the backend always connected to Prometheus without credentials. PR #168.
- **Settings → Prometheus API** (Contract 3, `GET`/`PUT /settings/prometheus`, `POST /settings/prometheus/test`, admin only): read the URL, mode and auth (never the secret), save the auth, test it. Also approved beyond the first spec: clearing (`kind: none`) skips the key check so an unreadable credential can be removed in key_mismatch mode, and switching between basic and bearer always needs a new secret. PR #168.
- **Two new probe failure reasons** (Contract 3, `/alerts/delivery-status` `reason`; Contract 2, `prometheus_unreachable`): `auth_failed` (401/403) and `credentials_unreadable`. Both make the probe fail, so they count toward `prometheus_unreachable` like the existing codes. PR #168.
