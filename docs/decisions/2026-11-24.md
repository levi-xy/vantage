# 2026-11-24

0.2.0 lite install: install scoping (PR #169) and the backend's own credentials for Prometheus (PR #168).

- **Prometheus auth setting** (Contract 2, `settings` row `prometheus_auth`): optional basic or bearer auth from the backend to Prometheus, the secret encrypted with the master key under its own row context, backed up and restored, and counted as a stored secret by the key check, restore and `rotate-master-key`. New; until now the backend always connected to Prometheus without credentials. PR #168.
- **Settings → Prometheus API** (Contract 3, `GET`/`PUT /settings/prometheus`, `POST /settings/prometheus/test`, admin only): read the URL, mode and auth (never the secret), save the auth, test it. Also approved beyond the first spec: clearing (`kind: none`) skips the key check so an unreadable credential can be removed in key_mismatch mode, and switching between basic and bearer always needs a new secret. PR #168.
- **Two new probe failure reasons** (Contract 3, `/alerts/delivery-status` `reason`; Contract 2, `prometheus_unreachable`): `auth_failed` (401/403) and `credentials_unreadable`. Both make the probe fail, so they count toward `prometheus_unreachable` like the existing codes. PR #168.
- **`vantage_install` label** (Contract 1): a fifth fixed label on every polled series and every scrape target, the install's id. Replaced the four-label set. PR #169.
- **Install id** (Contract 2, `settings` row `install_id`): made once, never changed, backed up and restored (a restore takes the backup's id). New. PR #169.
- **Fingerprints ignore `vantage_install`** (Contract 2, Alerts): so open alerts keep their identity on upgrade. PR #169.
- **Self-check on `vantage_build_info`** (Contract 2, System alerts; Contract 3, `/alerts/delivery-status` `reason`): `metrics_not_collected` reads this install's `vantage_build_info` instead of `up{job="vantage-backend"} == 1`, so the job name is free, and carries the reason `never_seen` or `stale`. PR #169.
- **Every query scoped to the install** (Contract 3, Install scope and `/query`): a fail-closed rewriter adds the `vantage_install` matcher to every selector, tolerant (`=~"<id>|"`) in `bundled` mode and exact in `external` mode, and refuses what it can't place (400 `query not supported`), including `info()`. `VANTAGE_PROMETHEUS_MODE` sets the mode; unset, it is `bundled` only for an unset or default `VANTAGE_PROMETHEUS_URL`. Until now queries were sent as written. PR #169.
- **`/metrics`** (Contract 3): every sample carries `vantage_install`; new gauge `vantage_build_info{version, commit}`. PR #169.
