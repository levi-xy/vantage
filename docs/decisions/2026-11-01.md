# 2026-11-01

From the "Trustworthy v0.1" plan (P0-3a, P0-5) and the M8.3 security review.

- **One alert event per series** (Contract 2, `alert_rules`, `alert_events`, "Alerts"): an alert is one series of a rule's result, identified by (rule_id, fingerprint); events are never deleted; rules are soft-deleted (`deleted_at`) and carry `revision`; events snapshot `rule_name`, `severity`, filtered `labels` and `instance_id`; `end_reason` and `summary` added. Older events have `fingerprint = "legacy"`. P0-3a.
- **Rule edits close events** (Contract 3, `/alerts/rules`): a new expression, scope, disabling or deleting closes the affected open events in the same transaction, with one message per rule and channel.
- **Event API** (Contract 3, `/alerts/events`, `/alerts/events/{id}/close`, `/ws`): events carry `instance_id`, `rule_name`, `severity`, `labels`, `fingerprint`, `end_reason` and `deliveries`; admins can close an open event by hand (404 unknown, 409 closed); `/ws` alert pushes carry `instance_id` and `fingerprint`.
- **Notification outbox** (Contract 2, `alert_notifications`, "Notification delivery"; Contract 3, `/alerts/delivery-status`; `/metrics`): durable delivery through an outbox written in the same transaction as the alert change, one dispatcher, folding, retry schedule, 24 h expiry, the 500-row summary, the "stuck" banner and the two delivery metrics. P0-5.
- **Poll failure tolerance** (Contract 3, instance `status`; `/metrics`): `down` only after N failed poll cycles in a row (`VANTAGE_DOWN_AFTER_FAILED_CYCLES`, default 3); `last_success_at` seeded from Prometheus at startup; `vantage_poll_consecutive_failed_cycles`.
- **Prometheus scrape limits** (Contract 4): `sample_limit: 50000`, `label_limit: 64`, `label_value_length_limit: 2048`, `body_size_limit: 16MB` on the service-discovery job. M8.3 finding M2.
