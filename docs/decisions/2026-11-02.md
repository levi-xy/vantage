# 2026-11-02

From the "Trustworthy v0.1" plan (P0-3b, P0-4, P0-6) and the dashboard work.

**NO DATA state (P0-3b)**
- `alert_events.state` gains `no_data`, with `no_data_reason`, `state_since` and `reminder_sent_at`; the open-event unique index covers `firing` and `no_data` (Contract 2, `alert_events`, "Alerts").
- "Alert states" (Contract 2): resolving needs two clean checks on two different polls; a missing value moves an alert to `no_data`, never to resolved; NO DATA message after 5 minutes and one reminder after 24 h (notification kind `no_data`).
- Rules: a rule scoped to one instance whose results carry no `vantage_instance_id` is refused at save; responses carry `recovery_mode` and `error` (Contract 3, `/alerts/rules`).
- Events and `/ws` pushes carry `no_data_reason` and `state_since` (Contract 3).

**System alerts and shared failures (P0-4)**
- `alert_events.source` and `system_kind` (`prometheus_unreachable`, `metrics_not_collected`, `evaluator_stalled`), reasons `prometheus_unreachable` / `metrics_not_collected` (Contract 2, "System alerts and shared failures").
- `channels.system_alerts` (boolean, default true), settable on create and PATCH (Contract 2, Contract 3).
- `/alerts/delivery-status` gains `system_alerts`; system alerts can't be closed by hand (409); events and `/ws` pushes carry `source` and `system_kind` (Contract 3).
- `GET /healthz` answers `200 {"status": "ok"}` or `503 {"reason": <code>}` with one fixed code; `GET /healthz/live` for container healthchecks.

**Master-key check and maintenance lock (P0-6)**
- `settings` rows `key_check` (backed up), `maintenance_lock` and `backend_heartbeat` (runtime state, never backed up or restored) (Contract 2).
- key_mismatch mode: polling, live rates and delivery stop, secret writes answer 503 `reason: key_mismatch`, a `key_mismatch` system alert (Contract 2, "Master-key check"; Contract 3, `/instances`).
- Maintenance mode: `restore` and `rotate-master-key` take the lock, the backend pauses and answers 503 `reason: maintenance` to state-changing requests except login, logout and `POST /query`; `startup-gate` before migrations (Contract 2, "Maintenance lock"; Contract 3 intro).
- `/healthz` codes `maintenance` and `key_mismatch` first; failed messages of a resolved `key_mismatch` alert don't count as stuck (Contract 3).

**Dashboards**
- `dashboards.position`; several dashboards: list, create (empty or copy, at most 50), rename, move, delete (not the last), open to any role; the first is the main one at `/`; create, rename/move and delete audited, layout saves not (Contract 2, Contract 3, `/dashboards`).
- `live_rate` follows the main dashboard's throughput card; other dashboards show the Prometheus rate (Contract 3, `/ws`).
